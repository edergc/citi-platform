Instalar el Agente CITI en un servidor nuevo

Descarga, extrae, ejecuta. El instalador trae todo incluido — ni siquiera necesitas Python en el servidor nuevo.

El agente se conecta hacia CITI Core (no al revés) y mantiene la conexión abierta: no necesitas abrir puertos de entrada en el servidor nuevo, solo permitir la salida hacia el puerto 8010.

Sistema operativo
Windows Server
Requiere instalar

Acceso
Administrador local
01

Descarga el instalador

En CITI, ve a Servidores → (elige o crea el servidor) y haz clic en "Descargar instalador". Se genera al vuelo un .zip único para ese servidor (~14 MB), con el token de enrolamiento, la URL de CITI y el hostname ya incrustados adentro.

Ese botón llama directo al backend de CITI por LAN — no depende de ningún sitio externo.

02

Cópialo al servidor nuevo y extráelo

Lleva el .zip al servidor (USB, carpeta compartida, lo que tengas a mano) y extráelo completo en cualquier carpeta, por ejemplo C:\CITI-Agent. Adentro encontrarás citi_agent.py, enroll.py, nssm.exe, install.bat, install.ps1 y una carpeta python\ — ese es el intérprete de Python ya preparado con todo lo que el agente necesita.

Extrae el .zip completo. La carpeta python\ pesa ~30 MB descomprimida; si el antivirus o una copia a medias la deja incompleta, el instalador fallará en el paso siguiente.
03

Ejecuta install.bat

Doble clic sobre install.bat. Se autoeleva a Administrador (aceptas el aviso de Windows) y hace todo solo, sin abrir PowerShell a mano:

Paso internoQué hace
EnrolamientoUsa el Python incluido para llamar a enroll.py con el token ya incrustado — no hay nada que escribir.
Servicio de WindowsRegistra e inicia CitiAgent con NSSM, apuntando al Python incluido.

Termina con un mensaje verde "Listo" o, si algo falla, un mensaje rojo explicando qué revisar.

04

Verifica en CITI

Entra a Servidores → (este servidor) en el panel. En menos de 15 segundos deberías ver:

Qué mirarEsperado
Estado del agenteAgente activo
Último latido"hace unos segundos", refrescando solo
CPU / RAM / DiscosValores reales del servidor, no en blanco

Si algo no aparece, revisa logs\service-stderr.log dentro de la carpeta del agente en el servidor nuevo — ahí queda cualquier error de conexión.

Problemas comunes

SíntomaCausa probable
"No se encontró el intérprete de Python incluido"El .zip se extrajo incompleto — vuelve a extraerlo completo (ver aviso del paso 2).
El agente nunca queda "activo"El servidor nuevo no puede alcanzar 172.20.1.51:8010 — revisa firewall/proxy de salida.
El enrolamiento fallaToken vencido o ya usado (cada .zip trae uno de un solo uso). Descarga un instalador nuevo desde el panel.
El servicio no arrancaRevisa con nssm.exe edit CitiAgent dentro de la carpeta extraída que las rutas apunten ahí.

Instalación manual (avanzada, opcional)

Si prefieres usar tu propia instalación de Python 3.12+ en vez del intérprete incluido, puedes hacerlo a mano con los mismos citi_agent.py/enroll.py y el botón "Generar solo el token" del panel:

PowerShell — carpeta del agente
python -m venv .venv
.venv\Scripts\pip install websockets==14.1 httpx==0.28.1 psutil==6.1.1
.venv\Scripts\python enroll.py --core-url http://172.20.1.51:8010 --server-id <id> --token <token>
.\nssm.exe install CitiAgent "%cd%\.venv\Scripts\python.exe"
.\nssm.exe set CitiAgent AppDirectory "%cd%"
.\nssm.exe set CitiAgent AppParameters "-u citi_agent.py"
.\nssm.exe set CitiAgent Start SERVICE_AUTO_START
.\nssm.exe start CitiAgent

Esto requiere que ese servidor tenga salida a internet (o un índice de paquetes propio) para instalar las dependencias — el instalador con un clic no necesita nada de esto.
